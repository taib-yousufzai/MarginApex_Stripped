================================================================================
                               THE PROBLEM
================================================================================

Your Position Analysis:
- Opened position: Live P&L showed -₹3.5
- Closed position: History showed -₹4.75
- Difference: ₹1.25 unexplained loss

Root Cause:
- Database stores exit_buffer = 0.0017 (decimal form)
- 7 files were dividing by 100: 0.0017 / 100 = 0.000017 (100x too small!)
- This made exit prices barely discount from LTP
- Live P&L (using TradeEngine) was correct
- Stored P&L (using close routes) was wrong

================================================================================
                                THE FIX
================================================================================

Files Changed: 7
Lines Changed: ~15 total
Pattern: Removed all /100 divisions and corrected fallback defaults

Files Fixed:
1. ✅ lib/orderMatching.ts
2. ✅ app/api/positions/close/route.ts
3. ✅ app/api/positions/[id]/close/route.ts
4. ✅ app/api/cron/auto-square-off/route.ts
5. ✅ app/api/admin/positions/[id]/sqoff/route.ts
6. ✅ app/api/admin/positions/[id]/route.ts
7. ✅ app/api/admin/orders/square-off-all/route.ts

Change Pattern:
FROM: const exitBuffer = (segSetting?.exit_buffer ?? 0.17) / 100;
TO:   const exitBuffer = Number(segSetting?.exit_buffer ?? 0.0017);

Result: Both live and stored P&L now use same correct buffer calculation ✓
